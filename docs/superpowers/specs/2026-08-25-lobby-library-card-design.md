# 大厅解法库卡片 + 首页返回大厅

日期：2026-08-25  
状态：已口头确认方案，待实现

## 1. 目标

1. 大厅将「24 点 · 解法库」做成与游戏同级的**第三张入口卡片**（方案 A）。
2. 各卡片入口的**未开始首页**提供「返回大厅」（方案 A：仅首页，不含设置页）。

## 2. 非目标

- 不解法库页列表改版。
- 不把解法库写入 `GET /api/v1/games` 游戏目录。
- 不在挑战进行中 / 设置页强制加「返回大厅」（设置页保留现有「返回」到游戏首页）。

## 3. 大厅

| 卡片 | 路径 | meta |
|------|------|------|
| 24 点挑战 | `games/24points/play.html` | 可玩（可由 API 刷新） |
| 舒尔特挑战 | `games/schulte/` | 可玩 |
| 24 点 · 解法库 | `games/24points/library.html` | 查阅 |

- 文案：浏览整数解与题型（简述即可）。
- 删除底部 secondary 文字链「24 点 · 解法库」。
- 第三卡为静态 HTML；API 仍只更新两个游戏卡的 `href`/`meta`。

## 4. 返回大厅

统一文案：`← 返回大厅`，样式沿用现有 `.linkish`（或解法库页等价链接样式）。

| 页面 | 位置 | 链接 |
|------|------|------|
| 24 点 `play.html` 首页 | 模式卡下方（可与「查看解法库」并列） | `/`（服务根）或相对到大厅 |
| 舒尔特首页 | 已有则核对可用 | 同上 |
| 解法库 `library.html` | 品牌标题下方或页脚旁显著位置 | 同上 |

链接约定：在门户/uvicorn 下优先用绝对路径 `/`，避免深层相对路径踩坑；与现舒尔特一致即可。

## 5. 触点文件

- `web/index.html`（构建同步 `dist/web/index.html`）
- `generate_play.py` → 重生 `play.html`
- `generate_html.py` → 重生 `library.html`
- `web/games/schulte/index.html`（及 dist 同步）
- 可选：大厅相关测试断言第三卡与解法库链接

## 6. 验收

1. 大厅可见三张卡片，点第三张进解法库。
2. 24 点 / 舒尔特 / 解法库 首页均可一键回大厅。
3. 选难度设置页无需「返回大厅」；原有「返回」仍回游戏首页。
