# 24 点挑战 — 难度分级设计

**日期:** 2026-08-25  
**状态:** 已确认  
**范围:** 开局单轴难度选择；说明文案；构建期打分写入题库

---

## 1. 目标

在休闲 / 挑战开局前选择难度，按档抽题。页面展示档位说明。  
**不**单独暴露「数字范围」「是否重复」选项；二者融入 `hardness` 公式。

## 2. 六档（由易到难）

| id | 文案 | 分位（约） | 页面说明（三项写清） |
|----|------|------------|----------------------|
| `intro` | 入门 | 最低 ~12% | **数字范围**多为 1–9；**是否重复**常有重复；**解法难度**解多、步骤少 |
| `simple` | 简单 | 12%–28% | **数字范围**仍偏小；**是否重复**可重可异；**解法难度**解较多，偶用乘除 |
| `normal` | 普通 | 28%–50% | **数字范围**小到中等均衡；**是否重复**重/异都有；**解法难度**适中（推荐） |
| `hard` | 困难 | 50%–72% | **数字范围**更大数更多见；**是否重复**互异更多；**解法难度**解少，常要括号/整除 |
| `master` | 大师 | 72%–88% | **数字范围**大数常见；**是否重复**多为互异；**解法难度**解少、技巧高 |
| `god` | 大神 | 最高 ~12% | **数字范围**全库跨度；**是否重复**以互异为主；**解法难度**解极少、最刁钻 |

说明区固定三行格式：`数字范围：…` / `是否重复：…` / `解法难度：…`（`white-space: pre-line`）。

## 3. Hardness 公式（构建期）

对每个有解四元组，取最短参考解（表达式字符最短；并列取第一条）：

```
hardness =
  3.0 * (1 / log2(n_sol + 1))
+ 1.0 * ops
+ 1.5 * has_div
+ 0.5 * depth
- 2.0 * trivial
+ range_bonus
+ dup_bonus
```

| 项 | 定义 |
|----|------|
| `n_sol` | 该四元组解法条数 |
| `ops` | 参考解中 `+ - * /` 个数 |
| `has_div` | 参考解含 `/` 则为 1，否则 0 |
| `depth` | 参考解最大括号嵌套深度 |
| `trivial` | 含 `0` 或 `1`，或某个输入已为 `24` → 1，否则 0 |
| `range_bonus` | `max≤9` → 0；`9<max≤13` → 0.8；`max>13` → 1.6 |
| `dup_bonus` | 有重复 → −0.6；四数互异 → +0.6 |

全库算完后按 `hardness` 升序分位打 `tier`。某档题数过少（&lt; 30）时构建期打印警告。

## 4. 题库字段

```json
{ "n": [3, 3, 8, 8], "h": "((8/(3-8/3)))", "t": "normal" }
```

- `n`：四数  
- `h`：参考解（休闲「看参考解」）  
- `t`：档 id  

## 5. UI

1. 首页选休闲 / 挑战 → 进入设置页。  
2. 设置页：难度六档芯片；点中后说明区更新。挑战另选题量 5/10/20。  
3. 抽题仅从当前 `t` 对应池；池空则提示并回退到邻档（优先向普通方向）。

## 6. 非目标

- 不单独提供范围 / 重复过滤器  
- 不在页面展示 hardness 数值或公式  
- 不改解法库页
